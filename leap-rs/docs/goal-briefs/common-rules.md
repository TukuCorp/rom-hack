## Rules

- **Red/green:** write the failing test first, at the highest feasible level (real vendor bytes,
  the area sweep, values knowable from the area's own data). Run it and confirm it fails for the
  right reason before implementing. No mock tests.
- **Root causes:**
  - No workarounds keyed on table names.
  - Prefer evidence that doesn't depend on your own reading: header-stated counts,
    hand-measurable pitches, values that are knowable independently.
  - The crate's history is full of "findings" that turned out to be misreadings.
- Match the existing code and doc style. Doc comments say what is established and what isn't.
- The Rust reader and the Python tool must apply the same rules.
- **Two-attempt limit:** if the same bug survives two fix attempts, stop that item, record what
  you tried and the current state, and move on.
- **Don't commit or push.** Leave your changes in the working tree.
- Track progress with checkboxes in your own new dated `##` section of the repo-root
  `activeContext.md`. Don't touch earlier sections.
